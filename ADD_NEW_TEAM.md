# Добавление новых Kill Team — процедура для новой сессии

Вставь этот файл целиком первым сообщением в новую сессию Claude Code в
папке `Killteam new design`. Только процедура добавления команд — остальной
контекст проекта не нужен, читается по ходу из кода/game_data.json.

## Вход

PDF с правилами команды лежит в `incoming_teams/<Название>.pdf`. Портреты
(если готовы) — в `incoming_portraits/<Название>/`, имя файла ≠ обязательно
имя оператора (сопоставляй по роли/оружию на картинке, не по строке).

## Шаг 1 — Research report (обязательно, не пропускать)

На каждую команду — отдельный Agent (subagent_type: general-purpose,
параллельно, если команд несколько), читает PDF через Read с `pages`,
**не пишет данные**, только отчёт по секциям:
1. Название/фракция как в PDF.
2. Архетипы.
3. Операторы (required + pool) с кратким описанием уникальных способностей.
4. Faction rules/ploys/equipment.
5. **CRITICAL** — кандидаты в `factionChoices` (team-wide "выбери N из
   списка"): scope setup/game, можно ли выбрать вариант только один раз за
   партию.
6. **CRITICAL** — кандидаты в `statusTokens`: target friendly/enemy, простой
   вкл/выкл или стековый счётчик (с каким потолком, если в правилах нет —
   предложить произвольный).
7. Необычные weapon rules, которых может не быть в глоссарии.

Отчёты — пользователю. Дальше используй AskUserQuestion, чтобы согласовать
каждый пункт 5 и 6 (это НЕ формальность — subagent-черновики регулярно
путают токены-на-терреoriginalном маркере с токенами-на-операторе, и team-wide
resource pool с per-operator статусом; всё это нужно решать явно).

Частые паттерны решений:
- Team-wide resource pool (типа Communion points/Wrecka points) — схема
  `statusTokens` per-operator, не per-team. Обычно решают: завести как
  friendly-счётчик с произвольным max, привязанный "к любому оператору" —
  неточно, но даёт UI. Альтернатива — не заводить, оставить в тексте.
- Battlefield/terrain-маркеры (Pulsa marker, Storm marker, Demolition
  marker) — НЕ statusTokens (это не состояние оператора). Просто текст в
  ability/faction rule.
- oncePerBattle на factionChoices — если по правилам вариант можно выбрать
  только раз за игру (не просто переключать по раундам).

## Шаг 2 — Draft JSON

После согласования — снова по Agent на команду (параллельно), с точными
инструкциями (не давать агенту угадывать):
- Точная схема (сослаться на существующий блок в `game_data.json` как
  шаблон — `killTeams.<любая существующая команда>` и
  `factionEquipmentByTeam.<та же команда>`).
- Перевод: связки/глаголы/обычные слова — русский; официальные термины
  (Range, Piercing, Lethal, APL, Move, Save, Wounds, Atk, Dmg, Hit, control
  range, killzone, turning point, Strategic Gambit, Charge, Dash, FLY и
  т.п.) и названия оружия — английские внутри русского текста.
- Лор (курсивное художественное вступление в оригинале) — убрать из
  `text`, перенести в `lore.intro`/`lore.operatives[].text`.
- Уже согласованные `factionChoices`/`statusTokens` — продиктовать агенту
  готовыми (id/target/counter/max), не отдавать на додумывание.
- Явно попросить агента вернуть JSON в сообщении, **не писать файлы**.

## Шаг 3 — Проверка перед вставкой (обязательно)

Известные баги субагентов, ловить руками при мёрже:
- `&amp;` вместо `&` в архетипах (`"Seek & Destroy"`) — ломает
  сопоставление с `tacOpsByArchetype`.
- required-операторы с `count > 1` (например, 2 обязательных копии) агент
  иногда кладёт в `pool` с полем `count` — там оно игнорируется
  (`pool` использует `poolCounts`+`maxCopies`, не `count`). Должно быть в
  `required`.
- Лишние ключи не по схеме (`"lore": null` внутри операторского объекта
  и т.п.).
- Сверить пару спорных характеристик (необычные Dmg вроде "6/3") напрямую
  по PDF через Read с `pages` — субагенты иногда путают normal/critical.

Вставлять вручную через Edit (не доверять программной генерации файла
целиком) — так проще контролировать диф.

## Шаг 4 — Глоссарий

Если в способностях появились weapon rules с `*` (Detonate*, Skytorch* и
т.п.) — добавь короткую запись в `TERM_GLOSSARY` в `docs/js/app.js`, в
тоне соседних записей: `'Name': 'Name — особое правило конкретного
оружия; полное описание — в способностях этого оператора (ищи запись «*
Name»).'`.

## Шаг 5 — Портреты

`python3 tools/smart_crop.py --batch "incoming_portraits/<Команда>/" docs/img/portraits/<team-slug>/`
— rembg снимает любой фон (не только белый). Сопоставление файл→оператор
по роли/оружию на фото, не по имени файла. Прогнать питон-скриптом
(json.load → пройтись по `required`+`pool` → проставить `portrait`) —
надёжнее, чем руками редактировать JSON.

## Шаг 6 — Синхронизация и деплой

```bash
python3 tools/sync_release.py
```
Валидирует структуру, копирует в `docs/`. Поднять cache-busting `?v=...`
в `docs/index.html` (все `<link>`/`<script>` теги) на новую дату/суффикс.

Проверка в браузере (preview на `docs-static`, порт 8420): выбор команды,
архетипы без `&amp;`, ростер строится (включая required с count>1),
портреты грузятся без 404 (`read_network_requests`), новые
`factionChoices`/`statusTokens` кликаются и ведут себя как задумано.

**Никогда не `git commit`/`git push` без явного «деплой»/«залей» от
пользователя в этом же сообщении** — даже если до этого уже разрешали.

## Очистка

`incoming_teams/<Название>.pdf` и `incoming_portraits/<Название>/` —
рабочие папки, не архив. Удалять только после явного подтверждения
пользователя (спроси отдельно, это необратимо).

## Нужные тулы/скиллы этой сессии

- **Agent** (subagent_type: general-purpose) — параллельно, для чтения PDF
  (шаг 1) и для драфта JSON (шаг 2). Не смешивать этапы в одном агенте.
- **AskUserQuestion** — согласование custom-механик перед записью (шаг 1).
- **Read** с параметром `pages` — точечная проверка спорных характеристик
  по PDF напрямую (шаг 3), PDF тяжёлые, не грузить целиком без нужды.
- **Bash** — `smart_crop.py`, `sync_release.py`, python-скрипты для
  точечной вставки portrait-путей в JSON.
- **Edit** — вставка JSON-блоков в `game_data.json`/`docs/js/app.js`.
- Claude Browser preview tools (`preview_start` конфиг `docs-static`,
  порт 8420; при конфликте порта — завести временный alt-конфиг в
  `.claude/launch.json` на другом порту, не трогая чужой) — для
  браузерной проверки перед деплоем.
